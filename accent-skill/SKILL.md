# Презентации на библиотеке «Акцент» · v2.7

Версия 2.3 от 01.11.2026: макет — по алгоритму из пяти шагов; число пунктов меняется само (`items`); нехватка фактов — пробел на слайде, а не смена формы; числа сверяются с материалом.

Александр правит по готовой презентации, а не по тексту. Ему сложно давать правки по таблице
сюжета, легко — по слайдам. Но если слайд кривой или его форма не показывает главную мысль,
он застревает на этом и до редактуры не доходит. Отсюда задача навыка: **сразу отдать деку,
которая аккуратна и у которой каждый слайд формой показывает свою мысль**, — тогда
Александру остаётся редактура.

Разделение труда: модель отвечает за смысл — главная мысль слайда, отношение, которое должна
показать форма, выбор макета. Геометрию — отступы, воздух, кегль, ритм, цвет — делает движок.
Модель координаты не трогает.

## Четыре роли, без остановок

| Роль | Делает | Результат |
|---|---|---|
| **Редактор** | Аудитория и режим, сюжет, карточка каждого слайда: главная мысль (`thesis`) и отношение (`rel`) | Таблица сюжета (в отчёт) |
| **Архитектор** | По отношению — два кандидата из библиотеки, выбор по форме, план полей | Карта макетов (в отчёт) |
| **Сборщик** | `spec.yaml`, `check`, `build`; ошибки движка — решением, а не координатами | .pptx без ОШИБКИ |
| **Корректор** | Проверка в порядке Александра: аккуратно → форма показывает мысль → текст | Ответ Александру |

**Остановок до сборки нет.** Сюжет и выбор макетов не согласую — они уходят в отчёт.
Спросить до сборки можно только одно: если материал противоречит сам себе. Нехватка фактов — не повод
останавливаться: собери с пробелами (`[нужно: …]`, `figure: {gap: …}`), список — в ответе.
Аудитория не ясна — спроси вместе с готовой декой, а собери по умолчанию в `show`.

## Цикл работы

### 0. Подготовка (1 минута)
- `STATE.md` и `card.md` проекта: палитра (роли), шаблон клиента, футер, конфиденциальное.
  Палитры нет — спроси; жёлтый «Акцент» и HSE по умолчанию не подставляй.
- `pip install python-pptx pyyaml pillow` при необходимости.
- Материал сохрани файлом рядом со спецификацией: он пойдёт в `deck.source`.

### 1. Редактор — `references/slide-task.md`
1. **Аудитория → режим.** 1–3 человека вблизи или чтение без докладчика — `read`;
   10–50 человек, очно или онлайн — `show`; приложения и реестры — `reference` у этих слайдов.
2. **Карточка слайда:** действие читателя, главная мысль (вывод, а не тема), **отношение**
   (`navigation.md`: фокус, контраст, последовательность, иерархия, цепочка, обоснование,
   сравнение, количество, …), рабочая единица, обязательные поля, первый факт.
3. **Язык:** `references/language.md`. Текст из материала — выверенный: слова и местоимения
   не меняются, меняется раскладка.

### 2. Архитектор — выбор макета по алгоритму (`references/navigator.md`, `references/navigation.md`)
Каталог целиком не читай: в библиотеке 235 макетов. Решение по каждому слайду — пять шагов, всегда в этом порядке.
Есть ТЗ от навыка deck-brief (`ГГГГ-ММ-ДД_…md`) — макеты и пробелы уже предложены: сверь их этими же шагами.
Пробел «решить: …» — не плашка, а содержание слайда выбора: вопрос, варианты из ТЗ, позиция Александра с пометкой
«предложение».

1. **Мысль и отношение.** Одна строка: что зритель поймёт (`thesis`) и какое отношение должна показать форма
   (`rel`: фокус, контраст, последовательность, иерархия, цепочка, сравнение, количество…).
2. **Названа модель — её макет.** Ансофф, BCG, SWOT, PESTEL, ADKAR, кривая изменений, бенчмарк, квартили…
   → `python scripts/accent.py find <модель>`: канонический макет первым. Модель узнают только по её рисунку.
3. **Иначе — по вопросу зрителя.** `accent.py nav` → группа (22 вопроса) → `accent.py nav G05`: работа каждого
   слайда одной фразой и «как выбрать» между соседями. Возьми **двух кандидатов** с нужным отношением; выбери тот,
   чья форма без чтения текста говорит `thesis`. Картинки — `references/gallery/<группа>.jpg`.
4. **Проверка макета — `accent.py slots <код>`.** Четыре строки сверху:
   - **схема или ДАННЫЕ** — на слайде с данными каждое число из материала, цифры образца не остаются;
   - **нужно в материале** — сверь с фактами;
   - **число элементов** — «ровно N — задано моделью» или границы (шаги 3–6);
   - **ПУНКТЫ СПИСКОМ** — если есть, пиши `items:`, движок сам возьмёт вариант на твоё число пунктов.
5. **Фактов не хватает — форму не меняй, ставь пробел.** Нет оценок рисков, сроков, цифр бенчмарка — слайд
   собирается в той же форме: `[нужно: …]` в тексте, `figure: {gap: "…"}` для рисунка (`adaptation.md`, «Пробелы»).
   Александр увидит деку и даст фактуру. Другой макет — только если без этих данных **меняется сама мысль**
   («где риски на поле» → «какие риски есть»), а не потому, что под соседний макет данные есть.

**Анти-правила** (так Кими ошибался в тестах 7–9):
- выбрать ровный список или таблицу, потому что «туда всё влезает» — нет: форма по отношению;
- модель (жизненный цикл, три горизонта) нарисовать таблицей — нет: её канонический макет;
- выбросить блок материала, потому что не нашлось макета — нет: `find`, соседняя группа или пробел;
- придумать число, оценку, срок ради макета — нет: пробел;
- угадывать номера полей — нет: `items:` или поля из `slots`.

**Запись решения в спецификации** у каждого слайда: `thesis`, `rel`, `use`, `alt` (второй кандидат) и `why`
(одной фразой: чем выбранный лучше соседа). Движок переносит это в отчёт — Александр видит, почему такая форма.

### 3. Сборщик — `references/adaptation.md`, эталон `examples/vektor/spec.yaml`
```bash
python scripts/accent.py check spec.yaml          # ёмкость, нерешённые поля, приметы ИИ-текста
python scripts/accent.py build spec.yaml out.pptx # сборка + сверка с deck.source + out.report.md
```
Движок сам: копирует образец, вписывает текст, меряет строки шрифтом Raleway, раздвигает
колонки и карточки, ужимает воздух, если чуть не влезло, убирает колонки целиком, переносит
или снимает выделение, убирает чужие оценки и статусы, ставит вывод под заголовок, красит
в палитру, делает заголовок настоящим заголовком, сверяет текст с материалом.

**ОШИБКА движка — решение Архитектора, а не повод двигать фигуры.** Другой макет **с тем же
отношением**, `drop`, два слайда. Отступать к ровному списку, потому что он собрался, нельзя.

### 4. Корректор — `references/quality.md`
Порядок — как смотрит Александр:
1. **Аккуратно.** `out.report.md`: ни одной ОШИБКИ, каждое ВНИМАНИЕ исправлено или пояснено.
2. **Форма показывает мысль.** Сверь `thesis` и макет: если форма не говорит мысль без чтения — слайд не прошёл.
3. **Текст.** Не придуман, не пересказан: фактура из материала, выверенная по `language.md`.
4. **Сверка с deck.source** в отчёте: каждая строка исходника есть в деке, ничего лишнего.

**Если ошибка — не объясняй, исправь.**

## Структура репозитория

```
├── SKILL.md                    # этот файл
├── scripts/
│   ├── accent.py               # движок: nav, find, slots, check, build
│   ├── build_manifest.py       # генерация manifest.json из library.pptx
│   ├── canvas.py               # рисование фигур
│   ├── figures.py              # схемы и диаграммы
│   └── fonts.conf              # настройки шрифтов
├── assets/
│   ├── library.pptx            # 235 образцов макетов
│   ├── manifest.json           # описание полей каждого макета
│   ├── groups.json             # группы навигатора
│   ├── relations.json          # отношения и модели
│   ├── variants.json           # варианты списков
│   └── fonts/                  # Raleway (OFL)
├── references/
│   ├── navigation.md           # 22 вопроса → группы → макеты
│   ├── navigator.md            # выбор макета по 5 шагам
│   ├── adaptation.md           # правила адаптации макетов
│   ├── slide-task.md           # карточка слайда
│   ├── language.md             # язык и стиль
│   ├── quality.md              # порядок проверки
│   └── gallery/                # превью макетов по группам
└── examples/
    └── vektor/
        └── spec.yaml           # эталон спецификации
```

## Быстрый старт

```bash
pip install python-pptx pyyaml pillow
python scripts/accent.py nav                    # посмотреть группы
python scripts/accent.py find ансофф            # найти макет Ансоффа
python scripts/accent.py slots A001             # посмотреть поля макета
```

Для сборки презентации:
1. Подготовь `spec.yaml` (см. `examples/vektor/spec.yaml`)
2. `python scripts/accent.py check spec.yaml`
3. `python scripts/accent.py build spec.yaml out.pptx`
